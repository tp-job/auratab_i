Project AuraTab

Root Cause (สาเหตุรากเหง้า)

ความซับซ้อนและกระจัดกระจายในการเข้าถึง (Fragmented & High-Click Access): เว็บไซต์หรือแอปพลิเคชันที่ใช้งานเป็นประจำถูกกระจัดกระจายอยู่ตามช่องทางต่างๆ (เช่น Bookmark Bar, History, หรือต้องพิมพ์ URL ใหม่ทุกครั้ง) ทำให้ผู้ใช้ต้องเสียเวลาและลดประสิทธิภาพการทำงาน (Context Switching Cost)

ภาระในการจัดหมวดหมู่และอัปเดตข้อมูลด้วยตนเอง (Manual Maintenance Overhead): ระบบ Bookmark ดั้งเดิมของเบราว์เซอร์ขาดความยืดหยุ่น การจัดเก็บแบบโฟลเดอร์ค้นหายาก และการบันทึกรายการโปรดแบบทำด้วยตนเอง (Manual Entry) สร้างภาระให้ผู้ใช้จนไม่ได้อัปเดตรายการให้เป็นปัจจุบัน

ขาด visual hierarchy และการเข้าถึงแบบ One-Click: หน้า New Tab ดั้งเดิมไม่ได้จัดลำดับความสำคัญของเว็บโปรดตามสถิติการใช้งานจริง ทำให้สมองต้องใช้เวลาในการกวาดสายตาและค้นหา (Cognitive Load)

Requirements (ความต้องการของระบบ)

Automatic Data Retrieval (การดึงข้อมูลอัตโนมัติ):

เชื่อมต่อกับ chrome.topSites API เพื่อดึงรายการเว็บไซต์ที่เข้าบ่อยที่สุด (Most Visited) มาแสดงผลโดยอัตโนมัติ

เชื่อมต่อกับ chrome.bookmarks API เพื่อซิงค์รายการ Bookmark จากเบราว์เซอร์มาจัดเรียงในรูปแบบ Dashboard

Dynamic & Personalized New Tab (การปรับแต่งหน้าแท็บใหม่):

เปลี่ยนหน้า New Tab ดั้งเดิม (chrome_url_overrides) ให้เป็น Dashboard รวมเว็บโปรดแบบ One-Click Launch

Smart UI & Categorization (การออกแบบหน้าจอผู้ใช้):

จัดวาง Layout ในรูปแบบ Card / Grid ที่สะอาดตา มองหานาย และตอบสนองต่อขนาดจอ (Responsive Design)

แสดง Icon/Favicon ของแต่ละเว็บไซต์โดยอัตโนมัติเพื่อช่วยให้จำจดและคลิกได้รวดเร็ว

Performance & Data Privacy (ประสิทธิภาพและความปลอดภัย):

โหลดข้อมูลได้รวดเร็ว ไม่ทำให้การเปิดแท็บใหม่หน่วง (Low Latency)

ประมวลผลและจัดเก็บข้อมูลทั้งหมดอยู่ภายในเครื่องของผู้ใช้ (Local Processing) ไม่ส่งข้อมูลพฤติกรรมการเข้าเว็บออกไปยัง External Server
